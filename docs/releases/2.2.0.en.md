# NodeFlow 2.2.0

Panel **2.2.0** · Node Agent **2.2.0** · HAProxy renderer **v21**

Client stickiness in DNS pools with backup servers, copying routes between nodes, and a route template library. Two migrations (000056, 000057). The Agent is unchanged. Thanks to @fesevu (#19, #20).

## New

- **Client stickiness and `leastconn` in pools with backup servers (#19).** A DNS pool with a backup server now supports client stickiness (sticky) and `leastconn` balancing. A new failover route is created without stickiness by default.
  - Limitations: in backup-server mode, `leastping`/`leastconn` with a tolerance greater than 0 are rejected; `leastping` combined with `source` stickiness is rejected too.
  - A client stuck to a backup server stays on it until the stickiness entry expires, even after the primary server is back.
- **Copying routes between nodes (#20).** A route can be copied to another node. The copy is created as a disabled draft — check the ports and addresses and enable it manually.
- **Route template library (#20).** A route can be saved as a template and used to create new routes on any node. Templates store `schema_version`. Migration 000056 (`route_templates`).

## Fixes

- **Rendering of existing failover routes does not change.** Migration 000057 keeps the previous balancing for routes with the legacy `source_table`: such routes are republished once with an identical HAProxy config. Re-saving an old failover route in the UI also keeps its balancing.
- **Audit:** route copying (`route.copy`) and template actions (`route_template.*`) are written to the audit log.
- Clear error messages and names for copies/templates; the copy and template dialogs follow the panel's style.

## Upgrading from 2.1.0

1. **Panel.** Run the installer again:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/NodeFlow-dev/nodeflow/main/install.sh | sudo sh
   ```

   Manually: set `NODEFLOW_VERSION=2.2.0` in `/opt/nodeflow/.env` and run `docker compose pull && docker compose up -d`. The image applies migrations 000056 and 000057 itself.
2. **Node Agent — optional.** The Agent code did not change in 2.2.0; everything works with Agent 2.1.x. To keep versions uniform: "Settings → Node Agent" → "Update to 2.2.0".

Upgrading from 1.0.x? Read the [2.0.0 release notes](2.0.0.md) (Russian) first: they cover a one-time systemd drop-in for kernel pipe buffers.
