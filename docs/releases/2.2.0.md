# NodeFlow 2.2.0

Panel **2.2.0** · Node Agent **2.2.0** · HAProxy renderer **v21**

Закрепление клиентов в DNS-пулах с резервными серверами, копирование маршрутов между нодами и библиотека шаблонов. Две миграции (000056, 000057). Agent не менялся. Спасибо @fesevu (#19, #20).

## Новое

- **Закрепление клиентов и `leastconn` в пулах с резервными серверами (#19).** Для DNS-пула с резервным (backup) сервером теперь доступны закрепление клиентов (sticky) и распределение `leastconn`. Новый failover-маршрут по умолчанию создаётся без закрепления.
  - Ограничения: в режиме с резервным сервером `leastping`/`leastconn` с допуском (tolerance) больше 0 отклоняются; `leastping` вместе с закреплением по `source` тоже отклоняется.
  - Клиент, закреплённый за резервным сервером, остаётся на нём до истечения записи закрепления (expire), даже когда основной сервер вернулся.
- **Копирование маршрутов между нодами (#20).** Маршрут можно скопировать на другую ноду. Копия создаётся выключенным черновиком — проверьте порты и адреса и включите её вручную.
- **Библиотека шаблонов маршрутов (#20).** Маршрут можно сохранить как шаблон и создавать из него новые маршруты на любой ноде. Шаблоны хранят `schema_version`. Миграция 000056 (`route_templates`).

## Исправления

- **Рендер старых failover-маршрутов не меняется.** Миграция 000057 сохраняет прежнее распределение для маршрутов с устаревшим `source_table`: такие маршруты один раз публикуются заново с идентичным конфигом HAProxy. Повторное сохранение старого failover-маршрута в UI тоже сохраняет его распределение.
- **Аудит:** копирование маршрута (`route.copy`) и действия с шаблонами (`route_template.*`) пишутся в журнал аудита.
- Понятные ошибки и имена копий/шаблонов; диалоги копирования и шаблонов оформлены в стиле панели.

## Обновление с 2.1.0

1. **Panel.** Повторно запустите установщик:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/NodeFlow-dev/nodeflow/main/install.sh | sudo sh
   ```

   Вручную: в `/opt/nodeflow/.env` укажите `NODEFLOW_VERSION=2.2.0` и выполните `docker compose pull && docker compose up -d`. Миграции 000056 и 000057 применяет сам образ.
2. **Node Agent — необязательно.** Код Agent в 2.2.0 не менялся, всё работает с Agent 2.1.x. Для единообразия версий: «Настройки → Node Agent» → «Обновить до 2.2.0».

Обновляетесь с 1.0.x — сначала прочитайте [заметки к релизу 2.0.0](2.0.0.md): там однократный drop-in systemd для pipe-буферов ядра.
