# NodeFlow 2.0.0

Panel **2.0.0** · Node Agent **2.0.0** · HAProxy renderer **v21**

Первый крупный релиз после 1.0.8. Panel и Node Agent теперь выпускаются с
одной версией, Panel поставляется готовым Docker-образом
`ghcr.io/nodeflow-dev/nodeflow-panel:2.0.0` (linux/amd64 и linux/arm64), а
установщик больше ничего не собирает на сервере.

## Главное

- **Маршрутизация.** Режим «Фолбэк» заменил `any_tcp`/`destination_ip`;
  несколько серверов на маршрут (до 16) в режимах «Пул» и «Основной +
  резервные»; DNS-пул на уровне отдельного сервера (`server-template` +
  resolvers) и `preferred_ip` для статичного основного адреса.
- **Балансировка.** `roundrobin`, `static-rr`, `random` (1 или 2 выборки),
  `leastconn` («Меньше соединений») и `leastping` («Меньше задержка»,
  аналог Xray leastLoad). Для `leastconn` и `leastping` — стоимость сервера и
  IP (`cost`) и толерантность (`balance_tolerance`): серверы с близкой
  нагрузкой или задержкой считаются равными и делят клиентов по весу; веса на
  лету выставляет Node Agent через runtime API, без reload. Вес сервера,
  отдельные веса IP DNS-пула (`ip_weights`), плавный ввод (`slowstart`).
- **Закрепление клиента.** `none`, `source` (хеш IP: consistent или
  map-based, `hash-balance-factor`, группировка IPv6 по префиксу) и
  `source_table` (запоминание на `sticky_ttl`, таблица переживает reload через
  локальные `peers`). Размер «Авто» считается от RAM ноды.
- **PROXY protocol.** «Доверенные адреса» (`accept_proxy_from`): IP, подсети
  и **домены** (до 32 на маршрут; Node Agent резолвит A/AAAA и обновляет ACL
  через runtime API без reload), вариант «от всех»; health-check отправляет
  PROXY-заголовок (`check-send-proxy`).
- **Ограничение скорости в ядре.** `shaper_mode=kernel`: лимиты на IP
  клиента применяет Node Agent через nftables, HAProxy сохраняет splice.
- **Производительность.** Splice-буферы 1 МиБ, когда ядро позволяет (Agent
  сам поднимает `fs.pipe-max-size`), иначе 256 КиБ; кеширование и меньше
  аллокаций в heartbeat Agent; gzip, батч-запросы и индексы в Panel;
  immutable-кеш статических ассетов.
- **Наблюдаемость.** Prometheus `/metrics` в Panel (выключено по умолчанию,
  bearer-токен ≥ 32 символов, опциональный allowlist CIDR) с меткой
  `node_name`.
- **Интерфейс.** Новый редактор маршрутов с живым предпросмотром HAProxy,
  страница настроек на всю ширину, блок Node Agent с таблицей подписанных
  релизов, статус эндпоинта `/metrics`.
- **Поставка.** Готовый multi-arch образ Panel в ghcr.io; миграции БД
  встроены в образ (`panel-api migrate`); `install.sh` ставит и обновляет
  Panel без git и без сборки; Node Agent для linux/amd64 и linux/arm64 в
  assets релиза; CI и release-workflow в GitHub Actions.
- **IPv6-клиенты можно полностью выключить для нод без IPv6 (IPv4-таблицы)** —
  поле маршрута `client_ipv6` (миграция 000054).

## Изменения поведения

- **Версии.** Panel и Node Agent — 2.0.0. Проверки возможностей Agent
  (≥ 1.1.0, ≥ 1.1.1, ≥ 1.1.3) сравнивают версии численно, Agent 2.0.0
  проходит все.
- **Renderer v21.** Нода без настроенных pipe-лимитов ядра и без
  «Авто»-таблиц получает конфиг байт-в-байт как в v20. Когда heartbeat
  меняет факты ноды (ядро настроено, RAM перешла в другой 256-МиБ-бакет),
  Panel сама публикует новую ревизию (`node facts changed`).
- **Размер «Авто» stick-table** больше не фиксированные 100k:
  clamp(5 % RAM / 228 Б / N, 100k, 10m), где N — число «Авто»-таблиц на
  ноде; без данных о RAM — 1m. Явные размеры не меняются.
- **`tune.pipesize 1048576`** рендерится только для нод, где Agent
  подтвердил `fs.pipe-max-size ≥ 1 МиБ` и `pipe-user-pages-soft = 0`, иначе
  262144.
- **DNS-пул без sticky** снова распределяет клиентов по `balance source`,
  как в 1.0.8.
- Режим закрепления `sni` удалён (миграция 000052 переводит такие маршруты в
  `source`).
- Функции, требующие нового Agent, отклоняются с кодом 422
  (`kernel_shaper_requires_agent_1_1`, `leastping_requires_agent_1_1`,
  `ip_weights_requires_agent_1_1`, `leastconn_tolerance_requires_agent_1_1_1`,
  `pp_trusted_domains_requires_agent_1_1_3`), пока нода не обновлена.
- Удалён устаревший веб-интерфейс `web/`; Panel отдаёт только React-сборку.

## Миграции базы данных

Применяются автоматически при старте (`migrate` в compose):

| Миграция | Что делает |
| --- | --- |
| 000026 | `routes.accept_proxy_from` |
| 000027 | таблица `route_servers` (несколько серверов) |
| 000028 | `sticky_enabled` |
| 000029 | `match_mode = fallback`, NOT NULL-ограничения |
| 000030 | удаление `sticky_table_size`/`sticky_expire` |
| 000031 | `balance_mode`, `route_servers.dns_pool`, `preferred_ip` |
| 000040 | индексы производительности |
| 000041 | согласование `route_servers` и `balance_mode` |
| 000050 | `shaper_mode` |
| 000051 | `sticky_mode`, `sticky_ttl` |
| 000052 | `balance_algorithm`, разделение алгоритма и закрепления |
| 000053 | числовые размеры таблиц, стоимость IP, число выборок `random` |
| 000054 | `client_ipv6` (выключение IPv6-клиентов) |

Номера 000032–000039 и 000042–000049 не используются. Автоматического
отката миграций нет — перед обновлением установщик делает `pg_dump`.

## Обновление с 1.0.x

1. **Резервная копия.** Установщик сам делает `pg_dump` в
   `/var/backups/nodeflow/` и архив `/opt/nodeflow` (включая `.env`, `tls/`,
   `pki/`). При ручном обновлении сделайте это заранее.
2. **Panel.** На сервере Panel повторно запустите установщик:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/NodeFlow-dev/nodeflow/main/install.sh | sudo sh
   ```

   Он найдёт `/opt/nodeflow/.env`, сохранит `.env`, `tls/`, `pki/` и
   Caddy-сниппет, заменит `compose.yaml` на релизный, выполнит
   `docker compose pull && docker compose up -d`, дождётся Panel 2.0.0 и
   уберёт исходники 1.0.x (они остаются в архиве). При сбое возвращаются
   прежние `compose.yaml` и `.env`.

   Вручную: скачайте `compose.release.yaml` в `/opt/nodeflow/compose.yaml`,
   добавьте в `.env` строку `NODEFLOW_VERSION=2.0.0`, затем
   `docker compose pull && docker compose up -d`.
3. **Node Agent.** Установщик публикует подписанные релизы Agent 2.0.0
   (amd64 и arm64). Назначьте 2.0.0 нодам в «Настройки → Node Agent»:
   updater атомарно заменит бинарник и откатит его, если Agent не запустится.
4. **Однократно на каждой ноде, обновлённой с 1.0.x** (юнит systemd при
   self-update не меняется, а Agent 2.0.0 настраивает pipe-лимиты ядра):

   ```bash
   sudo install -d /etc/systemd/system/nodeflow-node-agent.service.d
   printf '[Service]\nReadWritePaths=-/etc/sysctl.d -/proc/sys/fs/pipe-max-size -/proc/sys/fs/pipe-user-pages-soft\n' \
     | sudo tee /etc/systemd/system/nodeflow-node-agent.service.d/20-kernel-pipes.conf
   sudo systemctl daemon-reload && sudo systemctl restart nodeflow-node-agent
   ```

   Без drop-in всё работает, но splice остаётся на 256 КиБ. Ноды,
   добавленные панелью 2.0.0, получают эти права сразу.

## Известные ограничения

- Домены в «Доверенных адресах» PROXY protocol перерезолвятся с
  фиксированным интервалом 30 с; TTL DNS-записей не учитывается.
- Четыре старых интеграционных теста PostgreSQL
  (`TestPGStoreCredentialRenewalIntegration`, `TestPGStoreDashboardOverview`,
  `TestPGStoreQuotaTrafficSplitsMonotonicDeltaAcrossHourlyWindows`,
  `TestPGStoreRouteRevisionRefreshesAllDesiredFingerprints`) падают на
  устаревших фикстурах (NOT NULL `sort_order`, эталонные fingerprint и
  часовой пояс). На поведение Panel это не влияет; в CI они выполняются как
  неблокирующие.
- Install kit содержит Agent только для linux/amd64; arm64-бинарник лежит в
  assets релиза отдельно.
