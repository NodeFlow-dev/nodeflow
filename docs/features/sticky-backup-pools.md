# Закрепление клиентов с резервными серверами

Роли серверов и распределение клиентов настраиваются независимо. В редакторе
маршрута выберите «Основной + резервные», затем «Запоминать клиента», алгоритм
первого сервера «Меньше соединений» и срок `24h`.

Для основного DNS-пула добавьте домен с включённым DNS-пулом первой строкой,
а резервный адрес — второй. Не задавайте «Основной IP», если нужно распределять
новых клиентов между всеми адресами основного домена. В меню строки можно
назначить несколько основных серверов. Проверки здоровья DNS-пула включены всегда.

Первое подключение нового IP выбирает доступный основной сервер по числу
соединений с учётом весов. Последующие подключения используют сохранённое
назначение. Если сервер недоступен, новые подключения могут перейти на другой
доступный сервер. Резерв предназначен для отказа всех основных, а не для
переполнения их нагрузки. Уже установленные TCP-соединения не переносятся.

`24h` — срок неактивности записи, не периодическая ротация. При CGNAT один IP
закрепляет всех клиентов за ним. Персистентное назначение на резерв может
сохраняться после восстановления основных: это не гарантия немедленного возврата.

Настройки сохраняются через API и при повторном открытии редактора. Старые
маршруты «Основной + резервные» без явных настроек распределения сохраняют
прежнюю генерацию. Для API сочетайте `servers[].backup` (без `balance_mode`, если
основных несколько) с `sticky_mode: source_table`, `sticky_ttl: 24h` и
`balance_algorithm: leastconn`. Для одного основного и последующих резервов
можно передать `balance_mode: failover`.

Ограничения сочетаний резервных DNS-пулов и «Основного IP» не меняются.

Используйте толерантность `0 %`. Управляемые агентом `leastping` и `leastconn`
с ненулевой толерантностью пока не разделяют основные и резервные серверы,
поэтому для этой топологии недоступны. Обычный `leastconn` работает в HAProxy
и не требует обновления агента.
