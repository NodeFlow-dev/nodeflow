Как установить Panel и подключить первую HAProxy-ноду

Инструкция рассчитана на чистый сервер Ubuntu или Debian. Команды можно выполнять последовательно сверху вниз.

Порядок важен. Сначала в Panel должен появиться подписанный релиз Agent — автоматический установщик публикует его сам, при ручной установке загрузите его в настройках. Затем добавьте ноду по IP и SSH-доступу — Panel установит выбранный либо новейший совместимый релиз.
0

Что лежит в комплекте

Две отдельные папки, каждая подписана по назначению.

01-PANELcompose.release.yaml

Production compose для готового образа ghcr.io/nodeflow-dev/nodeflow-panel, шаблон nodeflow.env.example, исходники nodeflow-panel-source.tar.gz и примеры reverse proxy.

02-NODE-AGENT-UPLOADnodeflow-node-agent-2.0.0-linux-amd64

Бинарник Agent. Его нужно загрузить в «Настройки → Node Agent» до установки первой linux/amd64-ноды.

Архитектура этого комплекта — linux/amd64. Для ARM64-нод скачайте nodeflow-node-agent-2.0.0-linux-arm64 из assets GitHub Release и опубликуйте его в Panel с архитектурой arm64.
1

Подготовьте сервер Panel

Нужен домен, публичный IP и чистый Ubuntu или Debian.

DNSA/AAAA-запись panel.example.com должна указывать на сервер Panel.
Минимум2 vCPU, 2 ГБ RAM, 15 ГБ диска, root или пользователь с sudo.
ПортКому нуженНазначение
22/tcpАдминистраторуSSH на сервер Panel
80/tcpИнтернетуACME и редирект на HTTPS
443/tcpБраузеруВеб-интерфейс через Nginx/Caddy
4200/tcpНодамПрямой защищённый mTLS-канал Agent → Panel
8080/tcpТолько localhostВнутренний HTTP upstream для reverse proxy
Ubuntu · общие зависимости
sudo apt update
sudo apt install -y ca-certificates curl openssl

# Если Docker ещё не установлен:
curl -fsSL https://get.docker.com -o /tmp/get-docker.sh
sudo sh /tmp/get-docker.sh

sudo docker version
sudo docker compose version

На следующем шаге установите только один reverse proxy: Nginx или Caddy.

UFW на сервере Panel
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 4200/tcp
sudo ufw enable
Если SSH работает не на порту 22, сначала откройте в UFW фактический SSH-порт и не закрывайте текущую SSH-сессию до проверки нового подключения.
2

Распакуйте и установите Panel

Автоматически или вручную.

Рекомендуемый вариант — standalone-скрипт. Он найдёт последний опубликованный GitHub Release, проверит compose.release.yaml и бинарники Agent по SHA256SUMS и запустит Panel из готового образа — на сервере ничего не собирается:

Установка последней версии из GitHub
curl -fsSL https://raw.githubusercontent.com/NodeFlow-dev/nodeflow/main/install.sh | sudo sh

Если install kit уже скопирован на сервер, перейдите в его папку и запустите:

Автоматическая установка с Caddy
sudo ./INSTALL-NODEFLOW.sh

Он запросит домен, проверит, что DNS указывает на публичный IP этого сервера, и предложит режим доступа — обычный вход NodeFlow либо дополнительную Caddy cookie-защиту. Docker, Caddy, секреты, HTTPS-конфиг, Panel и подписанные релизы Agent (amd64 и arm64) будут подготовлены автоматически. Firewall скрипт не меняет. Реквизиты сохранятся в nodeflow-credentials.txt домашней папки пользователя, запустившего скрипт.

Для ручной установки со сборкой образа из исходников на сервере выполните:

Установка Panel
sudo install -d -m 0750 /opt/nodeflow
sudo tar -xzf 01-PANEL/nodeflow-panel-source.tar.gz -C /opt/nodeflow
cd /opt/nodeflow

sudo ./scripts/install-panel.sh \
  panel.example.com \
  https://panel.example.com \
  0.0.0.0
Что означает 0.0.0.0 в последнем аргументе: только mTLS-служба Agent слушает внешний порт 4200. Веб-интерфейс всё равно остаётся на 127.0.0.1:8080.

Установщик оставляет прямой HTTP-доступ выключенным: ALLOW_INSECURE_HTTP=false. Не меняйте это значение при работе через Nginx или Caddy.

Установщик сам создаёт пароли PostgreSQL, admin token, CA для нод, серверный mTLS-сертификат и ключ подписи обновлений. Секреты сохраняются в /opt/nodeflow/.env, но не печатаются в терминал.

3

Настройте HTTPS reverse proxy

Выберите Nginx или Caddy. Одновременно использовать оба не нужно.

Сначала поставьте временный HTTP-конфиг для выпуска сертификата:

Nginx · сертификат и финальный конфиг
sudo apt install -y nginx certbot
cd /opt/nodeflow

sudo install -m 0644 docs/install/reverse-proxy/nginx-http-bootstrap.conf.example \
  /etc/nginx/sites-available/nodeflow
sudo sed -i 's/panel\.example\.com/ВАШ.ДОМЕН/g' \
  /etc/nginx/sites-available/nodeflow
sudo ln -sfn /etc/nginx/sites-available/nodeflow /etc/nginx/sites-enabled/nodeflow
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

sudo certbot certonly --webroot -w /var/www/html -d ВАШ.ДОМЕН

sudo install -m 0644 docs/install/reverse-proxy/nginx.conf.example \
  /etc/nginx/sites-available/nodeflow
sudo sed -i 's/panel\.example\.com/ВАШ.ДОМЕН/g' \
  /etc/nginx/sites-available/nodeflow
sudo nginx -t && sudo systemctl reload nginx

Готовый конфиг, который уже находится в папке 01-PANEL/reverse-proxy/:

nginx-nodeflow.conf.example
server {
    listen 80;
    listen [::]:80;
    server_name panel.example.com;
    return 308 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name panel.example.com;

    ssl_certificate /etc/letsencrypt/live/panel.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/panel.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    client_max_body_size 70m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header Connection "";
        proxy_read_timeout 75s;
    }
}
Caddy
sudo apt install -y caddy
cd /opt/nodeflow
sudo install -m 0644 docs/install/reverse-proxy/Caddyfile.example /etc/caddy/Caddyfile
sudo sed -i 's/panel\.example\.com/ВАШ.ДОМЕН/g' /etc/caddy/Caddyfile
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
Caddyfile.example
panel.example.com {
    encode zstd gzip
    request_body { max_size 70MB }
    reverse_proxy 127.0.0.1:8080 {
        header_up Host {host}
        header_up X-Real-IP {remote_host}
        header_up X-Forwarded-Proto https
    }
}
Не проксируйте порт 4200 через обычный HTTP location. Это отдельный mTLS listener Panel. Ноды подключаются прямо к https://ВАШ.ДОМЕН:4200.
4

Откройте Panel и войдите

Admin token хранится только на сервере.

Показать admin token
sudo sed -n 's/^PANEL_ADMIN_TOKEN=//p' /opt/nodeflow/.env
  1. Откройте https://ВАШ.ДОМЕН.
  2. Вставьте полученный token в форму входа.
  3. Не отправляйте token в чат и не храните его в истории команд.
5

Опубликуйте Node Agent

Без совместимого подписанного релиза Panel не начнёт установку ноды.

  1. Проверьте файл командой sha256sum -c nodeflow-node-agent-2.0.0-linux-amd64.sha256.
  2. Откройте Настройки → Node Agent (подписанные релизы).
  3. Версия: 2.0.0.
  4. ОС: linux.
  5. Архитектура: amd64.
  6. Выберите 02-NODE-AGENT-UPLOAD/nodeflow-node-agent-2.0.0-linux-amd64.
  7. Нажмите «Загрузить и подписать».
Panel подписывает бинарник собственным Ed25519-ключом. Нода проверяет подпись, SHA-256 и порядок релиза; при неудачном запуске updater возвращает прежний Agent.
6

Добавьте HAProxy-ноду

Panel установит опубликованный Agent по SSH и настроит защищённый канал.

1. Panel → НодыНажмите «Добавить ноду»
2. SSH-доступIP, порт, пользователь, пароль или ключ
3. УстановкаPanel копирует Agent и настраивает mTLS
  1. Убедитесь, что для архитектуры ноды опубликован совместимый Agent.
  2. Укажите название и IP ноды.
  3. Укажите SSH-порт и пользователя. Поддерживаются root, обычный пользователь с sudo, пароль и приватный SSH-ключ.
  4. Выберите версию Agent либо оставьте автоматический выбор новейшей совместимой.
  5. Выберите режим sudo. Если sudo требует пароль — заполните отдельное поле.
  6. Включите автооткрытие портов UFW, если Agent должен открывать listener-порты маршрутов.
  7. Нажмите «Получить ключ хоста», вручную сверьте fingerprint и подтвердите доверие.
  8. Нажмите «Установить Node Agent» и дождитесь статуса «Установлено».
После установки SSH больше не используется для обычного управления. Agent сам подключается к Panel по исходящему mTLS-каналу на порт 4200.
7

Как обновить Panel

Повторный запуск установщика на сервере Panel.

1. Проверить текущую Panel на сервере
cd /opt/nodeflow
sudo docker compose ps
df -h /opt/nodeflow
2. Обновить до последнего релиза
curl -fsSL https://raw.githubusercontent.com/NodeFlow-dev/nodeflow/main/install.sh | sudo sh

Найдя /opt/nodeflow/.env, установщик работает как апгрейдер: делает валидированный pg_dump и архив /opt/nodeflow в /var/backups/nodeflow, сохраняет .env, tls/, pki/ и Caddy-сниппет, ставит новый compose.yaml, скачивает образ и проверяет версию Panel. Установки, собранные из исходников, переводятся на готовый образ. При провале возвращаются прежние compose.yaml и .env; дамп остаётся, миграции БД автоматически не откатываются.

3. Проверить обновление
cd /opt/nodeflow
sudo docker compose ps
curl -fsS http://127.0.0.1:8080/healthz

После обновления Panel обновите Agent на нодах: «Настройки → Node Agent» → «Обновить до 2.0.0». Для нод, установленных версиями 1.0.x, см. раздел «Обновление с 1.0.x» в заметках к релизу 2.0.0 (однократный systemd drop-in для pipe-буферов ядра).

8

Проверьте результат

Четыре короткие проверки после установки или обновления.

Сервер Panel
cd /opt/nodeflow
sudo docker compose ps
curl -fsS http://127.0.0.1:8080/healthz
curl -I https://ВАШ.ДОМЕН/
sudo ss -lntp | grep -E ':(4200|8080)\b'
Подключённая нода
sudo systemctl is-active nodeflow-node-agent haproxy
haproxy -v
sudo ufw status

Нормальный результат: контейнеры healthy, Panel отвечает по HTTPS, порт 8080 слушает только 127.0.0.1, нода видна онлайн, Agent и HAProxy active.

Panel не открывается по HTTPS
Проверьте sudo nginx -t, sudo journalctl -u nginx -n 50 и sudo docker compose logs --tail=80 panel-api.
Нода не устанавливается
Проверьте SSH-доступ, sudo-пароль, подтверждённый fingerprint и доступ ноды к ВАШ.ДОМЕН:4200. Порт 8080 ноде не нужен.
Нода установилась, но UFW не открывает listener
На странице ноды выберите UFW «Авто» или переустановите Agent с включённым разрешением автооткрытия.
